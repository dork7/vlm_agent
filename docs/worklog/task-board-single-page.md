# Worklog: Task board on a single page

## 2026-11-19
- Grilled the design with the Owner and settled the model: Templates in the main list, per-List copies, idempotent "Create & copy link" with name entered on first open, Duplicate List.
- Wrote `.scratch/task-board-single-page/spec.md` (Status: ready-for-agent). Test seams agreed: HTTP workflow seam plus one store-migration test.
- Next: split into tickets, then implement. ADR 0007 and the `GLOSSARY.md` update are part of the implementation.
- Prototyped five UI variants in `src/assign/prototype-board.ts` (A to F). Variant F (select and share, side by side) chosen. Delete uses confirm instead of undo; rename added to the spec.
- Split the spec into tickets `issues/01` to `08`, all ready-for-agent. Prototype still uncommitted on `main`; it should go to a throwaway branch before ticket 03 removes it.
- Added retention requirement: nothing hard-deleted; soft delete with `deletedAt`/reason for Tasks, Lists, People; Done copies kept with `doneAt`. Updated spec and tickets 01, 02, 08. No analytics UI in scope.
- Breakdown approved by the Owner: split into 9 tickets (`issues/01` to `09`), retention as its own ticket 02, Variant F as the layout in ticket 05. Tickets 01, 02 and 04 can start first.
- Ticket 01 done on branch `tb-01`: `kind` (`template`/`copy`) on Tasks with idempotent backfill in `openAssignStore`; existing create/attach/detach/delete-List flows keep `kind` in step; ADR 0007 and Template glossary entry added.
- Ticket 02 (tb-02): Task, List and Person deletes are now soft (`deletedAt` + `deleteReason`); `live` filter applied to every Task/List/People read in workflow and the Assignee stream; Task `doneAt` recorded (cleared on reopen); deleted Person `nameLower` is rewritten so the name can be reused. Create-failure rollbacks stay hard deletes. Feed still resolves deleted titles from events.
- Ticket 03 (tb-03): Add to List and Create List now insert independent copies of Templates (title, tags, instruction, Deadline; open, no Note; `templateId` kept for display only). Removing a copy and deleting a List soft-delete only copies (`removed`, `list-deleted`); deleting a Template soft-deletes only the Template (`template-deleted`). Live `list.add`/`list.remove` events unchanged but now carry the copy id. Re-adding a Template after removal leaves the old Removed row and shows a new Additional Task. Tasks page still lists Templates and copies together until ticket 05.
- Ticket 04 done on branch `tb-04`: Assignment `personId` optional; `POST /assign/lists/:id/link` creates the unassigned link once (idempotent, returns `{url}`); first open of `/l/:code` asks for a name (`POST /l/:code/name`) and binds the Person; Board shows "Awaiting name". The Create & copy link button itself is left to ticket 05.
- Ticket 05 (tb-05): `/assign/tasks` is now the single-page board (Variant F, server-rendered): Templates column (quick-add form, tick boxes, "in N lists", Add to List bar) beside a sticky Lists panel (expandable List rows with pill Not shared / Awaiting name / Person, progress, count, copies with done toggle and ✕ remove, sharing, assign, rename, delete dialog; progressive-JS Create & copy link). Stacks at 900px; 44px targets and 16px inputs on touch/narrow. `GET /assign/lists` and `GET /assign/lists/:id` redirect to the board (`?list=ID#list-ID` opens that List); the Lists nav item, list-sidebar and Task layout toggle (task-view.ejs and its test) are removed. Prototype module was never on this branch.
