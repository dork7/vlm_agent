# UI/UX and accessibility review: Task assignment (branch task-assignment-refresh)

Method: static read of `src/assign/workflow.ts`, `views/*.ejs` (incl. `theme.ejs`, `task-view.ejs`, login/nav views), spec stories 1-64 and GLOSSARY.md. Pages were not rendered. Contrast ratios were computed from the token values in `theme.ejs`. Line numbers refer to the current files. Most markup lives in single very long template-literal lines in `workflow.ts`, so the line number is the line of the template, not a sub-position.

## Summary

The refresh meets the spec's structural asks. There is a native-dialog Add Task, a collapsed disclosure row, plain-form status buttons, a Lists sidebar, Additional/Removed/Overdue markers that use text as well as colour, distinct revoked/replaced messages, and a good skip link, theme toggle and focus-visible style. The weaknesses are in how those pieces behave together:

- Status buttons redirect away from the context they were clicked in, and give no feedback.
- Buttons are not named per Task for screen readers.
- Each Task has two "Note" fields for the Assignee, and the Owner sees two on the Task page.
- Interactive links sit inside `<summary>`.
- Live reload discards UI state.
- Validation failures are generic and drop input (except Add Task).
- Several contrast and non-text-contrast values fail WCAG 2.2 AA.
- The Settings page is on the legacy layout.

Counts: 4 High, 14 Medium, 14 Low.

## What's good

- Native `<dialog>` for Add Task, Create List and confirmations: Escape, focus trap and focus return to the opener (`pageScript`). Cancel gets `autofocus` in confirm dialogs, and each has `aria-labelledby`/`aria-describedby`.
- Disclosure rows use real `<details>/<summary>`, so keyboard expand works without script (story 49). Done keeps Reopen visible when collapsed (story 48).
- Status buttons are plain form posts and only valid moves are offered per state, identical on both sides. The Blocked reveal degrades to a direct post without JS.
- State is never colour-only. Status badges, "Overdue" text and badge, "Additional task", "Removed", Draft/Assigned and "(already in <List>)" are all text.
- Revoked vs replaced messages are distinct and show no Task detail. Stale posts on a dead link give the same page rather than a raw error.
- Live banners use `role="alert"`; the stale-page notice uses `role="status"` and does not clobber typing or a selection.
- Good basics: skip link, `lang`, `:focus-visible` ring with a theme-specific colour, labelled form fields with `aria-describedby` hints, `aria-invalid` plus `autofocus` on failed login and password fields, `aria-label` on List Remove buttons, `aria-pressed` on the view toggle, `aria-current` in nav, copy-link fallback with a status message, reduced-motion handling, `noindex` on Assignee pages.
- Light/dark tokens are mostly well chosen: body text, muted text, badges and the danger/warning pairs all pass 4.5:1 (checked: 4.9-6.8:1).
- Responsive structure: sidebar collapses to a horizontal nav under 48rem, Lists sidebar stacks, `overflow-wrap:anywhere` on rows, and the status row wraps.
- Anti-enumeration wording on login, a clear "why this extra step" on confirm-login, and an optional-password offer with Skip are clear and accessible.
